## 주요 리스크 상세

### [리스크 #1]: 타 파트너사 상품 데이터 노출

- **설명**: URL 파라미터 또는 API 요청 조작을 통해 다른 파트너사의 상품 데이터에 접근할 수 있는 위험
- **발생 조건**:
  - URL에 상품 ID 또는 파트너 ID가 노출되어 있고 서버에서 검증하지 않을 때
  - API 요청 시 파트너 ID를 클라이언트에서 전달받아 검증 없이 사용할 때
- **영향 범위**:
  - 타 파트너사 상품 정보 (가격, 재고, 판매 현황) 유출
  - 경쟁사 정보 노출로 인한 비즈니스 손해
  - 개인정보 보호법 위반 가능성
- **완화 전략**:
  1. 모든 API에서 세션의 파트너 ID와 요청 데이터의 파트너 ID 일치 여부 검증
  2. 상품 조회 시 파트너 ID 조건 필수 적용 (쿼리 레벨)
  3. 민감 데이터 접근 로깅 및 모니터링
- **담당자/일정**: 보안팀 검토 필요

### [리스크 #2]: SQL Injection으로 인한 데이터 유출

- **설명**: 검색 필드에 악의적인 SQL 구문을 삽입하여 데이터베이스를 조작하거나 정보를 유출하는 공격
- **발생 조건**:
  - 사용자 입력값이 SQL 쿼리에 직접 삽입될 때
  - 파라미터 바인딩 미적용
- **영향 범위**:
  - 전체 상품 데이터 유출
  - 사용자 정보 유출
  - 데이터베이스 손상 (DROP, DELETE 등)
- **완화 전략**:
  1. Prepared Statement 및 파라미터 바인딩 필수 적용
  2. ORM 사용 시에도 Raw Query 검토
  3. 입력값 화이트리스트 검증
  4. WAF(Web Application Firewall) SQL Injection 룰 적용

### [리스크 #3]: XSS 공격으로 인한 세션 탈취

- **설명**: 검색어나 URL 파라미터에 악성 스크립트를 삽입하여 사용자 세션을 탈취하는 공격
- **발생 조건**:
  - 사용자 입력값이 HTML에 그대로 출력될 때
  - URL 파라미터가 페이지에 반영될 때
- **영향 범위**:
  - 관리자/사용자 세션 탈취
  - 권한 도용으로 인한 데이터 조작
  - 피싱 페이지 삽입
- **완화 전략**:
  1. 모든 출력값 HTML 인코딩
  2. Content-Security-Policy 헤더 적용
  3. HttpOnly, Secure 쿠키 플래그 설정
  4. 프레임워크 기본 XSS 방어 기능 활성화

### [리스크 #4]: 일괄 처리 중복 실행으로 인한 데이터 정합성 오류

- **설명**: 일괄 판매중지/재개/삭제 버튼을 빠르게 여러 번 클릭하거나 동시에 여러 요청이 발생하여 데이터 정합성이 깨지는 상황
- **발생 조건**:
  - 사용자가 버튼을 더블클릭할 때
  - 네트워크 지연으로 인해 요청이 중복 전송될 때
  - 여러 탭에서 동시에 같은 상품을 처리할 때
- **영향 범위**:
  - 상품 상태 불일치
  - 중복 처리로 인한 오류
  - 삭제된 상품이 다시 표시되는 현상
- **완화 전략**:
  1. 프론트엔드에서 버튼 클릭 후 로딩 상태로 비활성화
  2. 백엔드 API 멱등성 보장 (동일 요청 중복 처리 방지)
  3. 낙관적 락(Optimistic Lock) 또는 비관적 락(Pessimistic Lock) 적용
  4. 트랜잭션 처리로 원자성 보장

### [리스크 #5]: 대용량 데이터 조회 시 성능 저하

- **설명**: 검색 조건 없이 전체 상품을 조회하거나 대량의 데이터를 한 번에 로드할 때 시스템 성능이 저하되는 상황
- **발생 조건**:
  - 파트너사의 상품이 수만 건 이상일 때
  - 검색 조건 없이 전체 조회
  - 페이지당 표시 개수를 최대로 설정
- **영향 범위**:
  - 페이지 로딩 지연 (5초 이상)
  - 서버 부하 증가
  - 다른 사용자 서비스 영향
- **완화 전략**:
  1. 페이지네이션 필수 적용 (서버 사이드)
  2. 최대 조회 건수 제한 (예: 10,000건)
  3. 인덱스 최적화 및 쿼리 튜닝
  4. 캐싱 전략 적용 (자주 조회되는 데이터)
  5. 대용량 조회 시 별도 배치 처리 안내

## 테스트 우선순위 권고

1. **Critical 등급 리스크 관련 테스트 케이스 우선 실행**
   - 타 파트너사 데이터 접근 차단
   - SQL Injection 방어
   - XSS 공격 차단

2. **High 등급 리스크는 회귀 테스트에 필수 포함**
   - 일괄 처리 중복 요청 방지
   - 대용량 데이터 조회 성능
   - 세션/권한 검증

3. **Medium/Low는 시간 여유 시 실행**
   - 엑셀 다운로드 타임아웃
   - 검색 조건 유지
   - 엑셀 수식 인젝션
